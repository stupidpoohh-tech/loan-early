# 조기상환 계산기

대출을 중간에 갚았을 때 **실제 순이득이 얼마이고 언제 돌아오는지** 계산하는 웹 도구입니다.

기존 대출계산기와 다른 점은 일부상환 후 금융사가 **기간을 줄이는지**, **월 납입액을 재산정하는지**를
구분한다는 것입니다. 같은 금액을 넣어도 이 하나로 이득이 3배 가까이 갈립니다.

**현재 v2 — 화면을 처음부터 다시 만드는 중입니다.** 계산 엔진과 테스트는 완성 상태이고,
`src/main.ts` 는 엔진 연결만 확인하는 뼈대입니다. 완성된 직전 화면은 `ui-v1` 브랜치에 있습니다.

## 실행

```sh
npm install
npm test        # 엔진·포맷터 60개 테스트
npm run dev
npm run build   # 타입 검사 → 테스트 → vite build. 테스트가 깨지면 배포가 막힙니다
```

## 구조

```
src/
  loan.ts        계산 엔진 — DOM 참조 금지, 순수 함수만. 완성.
  loan.test.ts   명세 픽스처 + 성질 테스트. 완성.
  format.ts      원화·만단위·날짜 포맷터. 완성.
  format.test.ts
  main.ts        ← 여기서부터 새 화면을 만듭니다
index.html       최소 뼈대
```

계산은 UI와 완전히 분리되어 있습니다. `loan.ts` 는 DOM을 모르므로 어떤 화면 기술을 얹어도
그대로 따라가고, 계산이 틀리면 빌드 게이트가 배포를 막습니다.

## 계산 규칙

원리금균등 상환을 전제로, 회차마다 이자를 먼저 떼고 나머지를 원금에서 뺍니다.
**반올림 방향이 결과를 1원 단위로 좌우하므로 규칙을 고정했습니다.**

| 대상 | 규칙 | 이유 |
|---|---|---|
| 이자 | 반올림 `round(잔액 × 월이율)` | 총이자 픽스처가 이 방향에서만 맞습니다 |
| 중도상환수수료 | 절사 `floor(상환원금 × 요율)` | 실제 청구액이라 금융사 관행대로 원 미만을 버립니다 |
| 차액 재상환분 수수료 | 반올림 | 매달 같은 금액을 넣는다는 가정 위의 추정치입니다 |
| 재산정 납입액 | 올림 후 보정 | 닫힌 식은 이자 반올림 누적을 못 봐 회차가 하나 더 붙을 수 있어, `fitPayment()` 가 1원씩 올려 맞춥니다 |

**순이득(net)이 유일한 1차 지표입니다.**

```
순이득 = 앞으로 덜 내는 총액 − (갚는 원금 + 중도상환수수료)
```

## 명세와 다르게 간 곳 (엔진)

- **수수료 반올림** — 명세는 `round` 였으나 픽스처(`P=100,000 → 985원`)는 절사여야 맞습니다.
- **`P = 0` 처리** — 상환액이 0이면 재산정하지 않습니다. 안 하면 몇 원 오차로 가짜 손익이 생깁니다.
- **상환액 상한** — 잔액을 넘겨 입력해도 잔액까지만 씁니다.
- **부과기간 면제** — 국내 가계대출은 약관상 대부분 3년 뒤 수수료 면제라, 산정방식과 무관하게
  부과기간이 지나면 0으로 계산합니다(0 = 무기한). 금리가 낮고 면제가 코앞이면 미뤄 갚는 쪽이
  이기는 역전이 여기서 나옵니다 — "언제 갚을까" 축의 존재 이유입니다.
- **예시 대출** — 3,000만원 / 연 15% / 월 578,903원. 84회에 딱 떨어지는 납입액입니다.

## 배포

`dist/` 는 서버가 필요 없는 정적 산출물입니다. Vercel 은 main 푸시마다 자동 배포하고,
다른 브랜치는 프리뷰 URL 을 받습니다.
